Créer un cube multidimensionnel avec Analysis Services (MOLAP & MDX)

Joseph Konka @joekakone

03/03/2026 · 15 min

Big Data Analysis Services SSAS MOLAP MDX Visual Studio

Guide pratique pas à pas pour construire un cube multidimensionnel d'entreprise avec Visual Studio et SSAS : sources de données, DSV, dimensions, hiérarchies, mesures et déploiement.

S'abonner

Le mode multidimensionnel (Multidimensional Mode) est l'architecture historique et éprouvée de SQL Server Analysis Services (SSAS). Il repose sur le concept de cube OLAP (MOLAP - Multidimensional OLAP) et le modèle dimensionnel unifié (Unified Dimensional Model - UDM).

Dans ce modèle, les données sont pré-agrégées et stockées dans des structures multidimensionnelles optimisées sur disque. Il s'interroge avec le langage puissant MDX (MultiDimensional eXpressions).

Dans ce tutoriel complet, nous allons concevoir pas à pas un cube de vente d'entreprise basé sur le Data Warehouse AdventureWorksDW2022, en analysant les performances commerciales selon quatre axes majeurs : Temps (Date), Client (Customer), Produit (Product) et Territoire (Geography).

1. Créer le projet multidimensionnel dans Visual Studio#

Étape 1 : Nouveau projet#

Lancez Visual Studio 2022 depuis le menu Démarrer, puis cliquez sur le bouton Créer un projet :

Étape 2 : Sélectionner le modèle#

Dans la liste déroulante des modèles de projet, recherchez ou faites défiler jusqu'à Projet Multidimensionnel Analysis Services (Analysis Services Multidimensional and Data Mining Project) :

Cliquez sur Suivant pour passer à la configuration du projet :

Étape 3 : Nommer et créer la solution#

Nommez votre projet AdventureWorks_SSAS_Cube et cliquez sur le bouton Créer :

L'Explorateur de solutions affiche l'arborescence standard d'un projet décisionnel multidimensionnel : - Sources de données (Data Sources) : connexions aux bases SQL sous-jacentes. - Vues des sources de données (Data Source Views - DSV) : sous-ensemble logique des tables et relations. - Cubes : définitions des tables de faits, mesures et groupes de mesures. - Dimensions : axes d'analyse et hiérarchies d'attributs. - Rôles : sécurité et droits d'accès.

2. Configurer la source de données (Data Source)#

La source de données contient la chaîne de connexion et les informations d'authentification requises pour lire le Data Warehouse SQL Server.

Étape 1 : Lancer l'assistant#

Dans l'Explorateur de solutions, faites un clic droit sur le dossier Sources de données, puis sélectionnez Nouvelle source de données... :

L'assistant de création s'ouvre. Cliquez sur Suivant (Next) :

Étape 2 : Définir la connexion OLE DB#

Sélectionnez l'option Créer une source de données basée sur une connexion existante ou nouvelle puis cliquez sur le bouton Nouveau... :

Si un message d'avertissement relatif au fournisseur s'affiche, validez en cliquant sur OK :

Dans la fenêtre du Gestionnaire de connexions, configurez les paramètres de liaison : - Fournisseur : sélectionnez Fournisseur OLE DB Microsoft pour SQL Server ou Microsoft OLE DB Driver for SQL Server. - Nom du serveur : saisissez localhost ou . (votre instance locale SQL Server). - Authentification : conservez Authentification Windows. - Sélectionner ou entrer un nom de base de données : choisissez AdventureWorksDW2022.

Cliquez sur le bouton Tester la connexion. Dès que le message "La connexion de test a réussi" apparaît, cliquez sur OK :

La nouvelle connexion apparaît dans la liste. Cliquez sur Suivant (Next) :

Étape 3 : Informations d'emprunt d'identité (Impersonation)#

[!IMPORTANT] Les informations d'emprunt d'identité déterminent quel compte Windows sera utilisé par le service SSAS lors du traitement (Process) du cube pour interroger SQL Server. Sélectionnez Utiliser le compte de service (Use the service account).

Conservez le nom par défaut Adventure Works DW2022 et cliquez sur Terminer (Finish) :

3. Créer la vue de source de données (Data Source View - DSV)#

La Vue de source de données (DSV) est une couche d'abstraction essentielle dans SSAS Multidimensionnel. Elle isole le modèle décisionnel des modifications physiques de la base SQL et permet de renommer des colonnes, de créer des requêtes nommées ou d'ajouter des relations logiques sans modifier la base SQL Server.

Étape 1 : Lancer l'assistant DSV#

Dans l'Explorateur de solutions, faites un clic droit sur Vues des sources de données \(\rightarrow\) Nouvelle vue des sources de données... :

Cliquez sur Suivant (Next) :

Sélectionnez la source de données Adventure Works DW2022 créée précédemment, puis cliquez sur Suivant :

Étape 2 : Sélectionner les tables du schéma#

La liste de gauche affiche toutes les tables et vues disponibles dans la base relationnelle :

  1. Cliquez sur la table DimCustomer et cliquez sur le bouton fléché > pour la faire basculer dans la colonne Objets inclus à droite :

  1. Maintenez la touche Ctrl enfoncée et sélectionnez simultanément les tables :
  2. DimDate
  3. DimGeography
  4. DimProduct
  5. FactInternetSales

Cliquez sur le bouton > pour toutes les inclure :

Toutes les tables nécessaires étant incluses dans le volet droit, cliquez sur Suivant :

Validez en cliquant sur Terminer :

Le concepteur graphique s'ouvre, affichant le schéma avec la table de faits au centre reliée aux dimensions par leurs clés étrangères :

4. Concevoir la dimension Temps (DimDate)#

Une dimension dans SSAS représente un axe d'analyse métier. Commençons par structurer la dimension de référence pour toute analyse temporelle : DimDate.

Étape 1 : Assistant de création de dimension#

Faites un clic droit sur le dossier Dimensions \(\rightarrow\) Nouvelle dimension... :

Cliquez sur Suivant :

Choisissez l'option Utiliser une table existante (Use an existing table) puis cliquez sur Suivant :

Étape 2 : Définir la table source et la clé primaire#

  • Table principale : DimDate
  • Colonnes clés : DateKey
  • Colonne de nom : FullDateAlternateKey (permet d'afficher une vraie date lisible au lieu d'un identifiant numérique).

Cliquez sur Suivant :

Étape 3 : Sélectionner les attributs temporels#

Cochez les attributs d'analyse pertinents : - DateKey - FullDateAlternateKey - DayNumberOfWeek - EnglishDayNameOfWeek - DayNumberOfMonth - DayNumberOfYear - WeekNumberOfYear - EnglishMonthName - MonthNumberOfYear - CalendarQuarter - CalendarYear - CalendarSemester

Cliquez sur Suivant.

Étape 4 : Définir le type sémantique des attributs#

6. Enrichir les dimensions et créer des membres calculés MDX#

Dans l'Explorateur de solutions, les dimensions Dim Customer.dim et Dim Product.dim ont été créées :

Création d'une mesure calculée en MDX#

Dans le concepteur de cube, basculez sur l'onglet Calculs (Calculations) pour ajouter des métriques métier via le langage MDX :

Script MDX : Calcul de la Marge et du Taux de Marge
/* Calcul de la Marge Brute */
CREATE MEMBER CURRENTCUBE.[Measures].[Marge Brute]
AS [Measures].[Sales Amount] - [Measures].[Total Product Cost],
FORMAT_STRING = "Currency",
VISIBLE = 1,
ASSOCIATED_MEASURE_GROUP = 'Fact Internet Sales';

/* Calcul du Taux de Marge Brute en Pourcentage */
CREATE MEMBER CURRENTCUBE.[Measures].[Taux de Marge]
AS IIF(
    [Measures].[Sales Amount] = 0, 
    NULL, 
    [Measures].[Marge Brute] / [Measures].[Sales Amount]
),
FORMAT_STRING = "Percent",
VISIBLE = 1,
ASSOCIATED_MEASURE_GROUP = 'Fact Internet Sales';
